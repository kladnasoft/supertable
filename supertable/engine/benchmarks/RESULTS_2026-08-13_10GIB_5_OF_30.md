# 10 GiB, five-of-thirty-column, one-percent range comparison

Production `DUCKDB_LITE` and `ISLANDDB` executor paths were run against the
same deterministic local ZSTD Parquet corpus. DuckDB was the correctness
oracle and exact result columns, pandas dtypes, values, and ordering matched
before timing.

- Physical source: 10,737,429,031 bytes, 6,413,677 rows, 81 files.
- Public schema: 30 columns (plus three scan-visible internal/virtual columns).
- Query columns: `id`, `metric`, `dimension`, `payload_00`, `payload_01`.
- Predicate: contiguous 1% `id` range.
- File pruning: 81 to 2 files; 268,433,931 physical candidate bytes.
- Row-group pruning: 38 to 16 groups.
- Exact compressed selected chunks: 9,055,635 bytes.
- Exact decoded selected buffers: 72,445,080 bytes.
- Returned result: one aggregate row; no spill.

The local OS page cache was uncontrolled. Consequently `/proc/self/io` and
DuckDB reported zero physical reads on warm samples; these are warm engine
comparisons, not cold-storage or object-store network claims.

| Metric | DuckDB Lite | IslandDB |
|---|---:|---:|
| Cold wall time | 262.48 ms | 287.38 ms |
| Warm wall median (2 samples) | **124.58 ms** | 162.88 ms |
| Warm range | 118.93–130.23 ms | 153.45–172.32 ms |
| Relative warm speed | **1.31x faster** | 0.765x DuckDB speed |
| Cold process CPU | 563.53 ms | **413.44 ms** |
| Warm process CPU range | **137.79–149.32 ms** | 247.74–266.35 ms |
| Cold RSS peak delta | **20.28 MiB** | 64.14 MiB |
| Warm RSS peak delta | **0.04–0.06 MiB** | 6.67–8.81 MiB |
| Engine-managed memory peak | 3.31–3.85 MiB | n/a (RSS delta above) |
| Exact logical compressed scan | common 8.64 MiB | common 8.64 MiB |
| Physical disk read reported | 20 KiB cold, 0 warm | 0 (OS-cache hit) |
| Rows scanned/reported | 160,342 DuckDB profiler rows | 68,697 candidate rows |
| Selected row groups | profiler implicit | 16 |
| Spill | 0 | 0 |
| Result bytes | 36 | 37 Arrow bytes |

Interpretation: this highly selective query is planning/operator dominated
after file and row-group pruning reduce 10 GiB to 8.64 MiB of compressed
selected chunks. DuckDB Lite is the correct AUTO choice on this host: it is
about 23.5% faster by elapsed time and uses materially less warm incremental
RSS. IslandDB used less CPU on the first process-cold run, but more CPU and
memory on repeats. This result does not contradict IslandDB's advantage on
large narrow *full-range* projections, where much more selected data remains.

Reproduce:

```bash
python -m supertable.engine.benchmarks \
  --sizes 10gib --allow-large \
  --workloads range_1pct_5cols --repeats 2 \
  --payload-columns 26
```
